# 验证记录

这份记录区分“功能已验证”和“识别准确度”。本程序是可继续开发的本地原型。

## 已实际运行

- 环境：Linux、Python 3.12.14、OpenCV 4.11.0、NumPy 2.3.5、Pillow 12.3.0。
- `python -m unittest discover -s tests -v`：33 项测试通过。
- `node --check static/app.js`：JavaScript 语法检查通过。
- Chromium 153 中实际操作并验证：打开示例、自动识别、手动添加墙/门/楼梯多边形、撤销/重做、拖动墙线、删除、导出 PNG/SVG/JSON、重新导入工程、拒绝无效工程且保留当前数据。该流程无 JavaScript 页面异常。
- PNG 实际导出尺寸为 927 × 890，与示例原图一致。
- 检查了手工楼梯多边形内部像素，颜色符合绿色与底图各占 50% 的合成，允许 8-bit 量化 1 色阶差异。
- SVG 包含明确的 `fill-opacity="0.5"`。
- 检查了未标注白底位置的像素未被更改。
- 对示例图运行的是检测代码，没有根据文件名或预设坐标加载“识别答案”。

## Python 测试覆盖内容

检测器测试包含：空白/透明图片；非正方形和极窄图像；大图缩放后回到原始坐标；合成楼梯与平台；将对角交叉符号排除出开门圆弧证据；窗处连续墙线与门洞断开。

服务测试包含：图片格式、透明背景合成、EXIF 朝向、尺寸与文件大小限制、错误输入、参数边界、非常大的数值、真实本机 HTTP、静态文件类型、路径穿越拒绝、Host/Origin 检查、检测异常恢复与并发锁释放。

这些是行为和回归检查，并不是代表性平面图数据集上的精度评测。

## 已观察到的识别限制

- 能找到示例中的两组楼梯踏步，但自动楼梯多边形与建筑意义上的完整楼梯间不一定相同，尤其是出入口和不规则平台。
- 小门、双开门的合并位置、墙体变厚处、窄隔间和电梯附近仍需核对。自动墙线不是每一处都精确落在墙体中心。
- 灰色楼梯边框、栏杆、门扇、家具线都可能影响墙线；复杂符号也可能造成额外门候选。
- 窗户没有作为独立对象导出。跨窗连接依赖局部线形与间距，不能保证每一个窗段都连接正确。
- 自动算法针对清晰正交图，未完成复杂扫描、斜墙、曲线墙、密集文字和各类专业制图标准的泛化评测。
- 重新识别会替换自动候选并保留手工标注；必要时检查新候选与保留标注是否重复。

## 未完成的验证

- 没有训练或加载神经网络权重，也没有测试 GPU 推理。
- 没有墙/门/楼梯的人工真值测试集，因此没有 Precision、Recall、IoU 或“识别率”数值。
- Windows/macOS 启动脚本已编写，但本次没有在 Windows/macOS 实机运行；若启动失败，应让 Claude 从依赖安装和终端错误开始排查。
- 尚未验证真实物理尺寸、法规检查或疏散计算；本版只输出像素几何。
